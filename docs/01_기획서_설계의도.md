### 레퍼런스 영상 분석 결과 (영상 직접 확인)

- **그래픽 톤**: 플랫 셰이딩 3D 카툰. 캐릭터는 얇은 흰 팔다리 + 검은 외곽선 + 단색 유니폼(빨강 vs 청록/회색)의 단순한 실루엣. 바닥은 보라색 바탕에 잔잔한 대각선 패턴, 경기장 외곽에 스폰서 보드. 정보량이 적고 색 대비가 선명함.
- **조작 (화면 하단 안내문 그대로)**: `↓당겼다 ↑밀기 = 드라이브` / `↑올렸다 ↓내리기 = 커트` / `툭 = 블록`.
  → 마우스를 누른 채 **아래로 당겼다가 위로 밀면 드라이브**, **위로 올렸다가 아래로 내리면 커트**, 짧게 툭 치면 블록.
- **타이밍 가이드**: 공이 다가오면 캐릭터 주변 바닥에 **빨간 점선 원**이 생기고 좁혀지며 타점 타이밍을 알려줌. 캐릭터 머리 주변의 **파란 원**은 타격 가능 범위 표시로 보임.
- **타격 피드백**: 라켓 궤적을 따라 흰색 **스윙 트레일 호(arc)**, 타격 순간 작은 섬광, 타점 근처에 `PERFECT` 텍스트 팝업, 공 궤적 잔상.
- **HUD**: 좌하단 방송 중계 스타일 스코어보드(국기 + 이름 + 노란 점수 박스 + 서브권 화살표 ◀), 좌하단 `포핸드/백핸드` 자동 판정 표시, 하단 조작 안내 한 줄.
- **사운드**: 배경음악 없이 짧고 건조한 타격음/바운드음이 리듬감 있게 반복됨(파형 확인). 소리 자체가 타격감의 핵심.

## 1. 프로젝트 개요

- **무엇**: 링크 하나로 브라우저에서 바로 하는 3D 스쿼시 웹게임. 설치·로그인 없음.
- **왜**: 레퍼런스(탁구) 게임의 "마우스 스윙 한 번으로 느끼는 타격감"을 사방이 벽인 스쿼시로 옮기면, 벽 반사라는 새로운 재미가 생긴다.
- **누가**: 가볍게 링크로 들어와 몇 분 즐기는 캐주얼 유저. 스쿼시 룰을 몰라도 1분 안에 이해해야 함.
- **핵심 경험(이 3개가 살아있으면 성공)**
  1. 마우스 스와이프 한 번에 "딱!" 하고 맞는 손맛 (사운드 + 히트스톱 + 미세 진동)
  2. 앞벽·옆벽에 튕겨 돌아오는 공을 읽고 자리 잡는 재미
  3. 쉬움→어려움으로 갈수록 코트가 좁아져서 반응 속도가 시험되는 긴장감

## 3. 핵심 시스템 설계 의도

### 3-1. 코트

- 실제 WSF 규격을 기준(1.0배)으로 삼는다. 비율이 맞아야 "스쿼시처럼" 느껴진다.

| 항목 | 실제 규격 |
|---|---|
| 코트 길이 × 폭 | 9.75m × 6.40m |
| 앞벽 아웃 라인 높이 | 4.57m |
| 뒷벽 아웃 라인 높이 | 2.13m (옆벽 아웃 라인은 앞 4.57m → 뒤 2.13m 사선) |
| 서비스 라인(앞벽) | 1.78m |
| 틴(앞벽 하단 양철판) 윗선 | 0.48m (프로 0.43m) |
| 숏 라인 | 앞벽에서 5.44m |
| 서비스 박스 | 1.60m × 1.60m 정사각형, 숏 라인 뒤 좌우 |

- **뒷벽은 유리**(실제 프로 코트처럼)로 처리해 카메라가 뒷벽 바깥에서 들여다봐도 시야가 막히지 않게 한다. 첨부 이미지 1과 같은 구도.
- 틴은 공이 맞으면 "땡" 하는 금속음이 나야 한다. 스쿼시만의 정체성 있는 소리.

### 3-2. 난이도 = 코트가 좁아짐

- 공 속도·물리는 난이도와 무관하게 **동일**하게 두고, 코트가 작아지면서 공이 더 빨리 돌아오는 구조. 즉 "반응 시간"이 줄어드는 게 난이도의 본질.
- 라인/틴/서비스 박스 위치는 코트 크기에 **비례해서** 함께 줄어든다. (높이 관련 라인은 그대로 두는 것도 검토 — 플레이 테스트로 결정)
- 초기 제안값 (튜닝 대상, 반드시 설정값으로 분리):

| 난이도 | 길이 배율 | 폭 배율 | AI 성향 |
|---|---|---|---|
| 쉬움 | 1.00 | 1.00 | 반응 느림, 실수 잦음, 단조로운 드라이브 위주 |
| 중간 | 0.85 | 0.90 | 보통 반응, 가끔 드롭 섞음 |
| 어려움 | 0.70 | 0.80 | 빠른 반응, 플레이어가 뒤에 있으면 드롭 / 앞에 있으면 깊은 드라이브로 흔듦 |

- 1인 모드에도 같은 난이도 체계를 적용한다.

### 3-3. 조작 — 마우스 제스처 (레퍼런스와 동일 메커니즘)

| 제스처 | 샷 | 스쿼시에서의 의미 | 공의 성격 |
|---|---|---|---|
| 누른 채 **아래로 당겼다가 → 위로 밀기** | **드라이브** | 앞벽 높게 맞고 코트 뒤쪽 깊숙이 가는 강한 샷 | 빠름, 앞벽 중상단, 뒤쪽 깊게 |
| 누른 채 **위로 올렸다가 → 아래로 내리기** | **드롭** | 틴 바로 위를 살짝 맞혀 앞쪽에 툭 떨어뜨리는 샷 | 느림, 앞벽 하단, 앞쪽 짧게, 백스핀 느낌 |
| **짧게 툭 클릭** | 블록(발리 리턴) | 급할 때 그냥 받아넘기기 | 중간 속도, 정확도 낮음 |

- **제스처 해석 의도**
  - 최종 스트로크 방향(위로 밀었나 / 아래로 내렸나)이 샷 종류를 정한다.
  - 스트로크 **속도**가 파워(공 속도)를 정한다. 단, 상한이 있어 마구 흔든다고 무조건 세지지 않음.
  - 스트로크의 **좌우 기울기**가 조준 방향을 정한다 (스트레이트 ↔ 크로스코트).
  - 제스처는 공이 타격 범위에 들어오기 직전부터 받아두는 **입력 버퍼**를 둬서, 살짝 이른 입력도 인정한다.
- **타이밍 판정**: 공이 이상적인 타점에 가까울 때 휘두르면 `PERFECT`, 조금 어긋나면 `GOOD`, 많이 어긋나면 `LATE/EARLY`. 판정이 좋을수록 의도한 방향·파워가 정확하게 나가고, 나쁠수록 방향이 흔들리고 틴/아웃 확률이 올라간다.
- **포핸드/백핸드**: 공이 캐릭터 오른쪽이면 포핸드, 왼쪽이면 백핸드 — 자동 판정, 레퍼런스처럼 화면에 작게 표시.
- **타이밍 가이드 UI**: 레퍼런스처럼 예상 타점 바닥에 줄어드는 링 + 캐릭터 주변 타격 범위 원.
- **이동**: 기본은 키보드 `WASD / 방향키`로 캐릭터 이동, 마우스는 스윙 전용.
  - 쉬움 난이도(또는 옵션)에서는 **자동 위치 보조**: 손을 안 대면 캐릭터가 예상 타점 쪽으로 천천히 따라감. 마우스만으로도 플레이 가능하게.
  - ※ 이 부분은 레퍼런스 영상만으로 확정이 안 돼서 제안한 방식임. (6절 미결정 항목 참고)
- **이동 감각**: 출발/정지/방향 전환 시 미끄러지는 관성을 약간 주고, 급정지·급전환 순간에 신발 스퀵 사운드가 난다.

### 3-4. 룰 (AI 대전 모드)

현재 WSF 공식 PAR(Point-A-Rally) 방식 기준.

- **게임(세트)**: 랠리 승자가 서브권과 상관없이 1점. **11점 선취**. **10:10이면 2점 차**가 날 때까지 계속.
- **매치**: **3전 2선승**(2게임 선취).
- **서브권**: 랠리를 이긴 쪽이 다음 서브. 같은 선수가 연속 서브할 때는 서비스 박스를 좌↔우 번갈아 사용. 서브권이 넘어가면 새 서버는 박스를 선택(게임에선 자동으로 좋은 쪽 선택 또는 오른쪽 기본).
- **랠리 중 공의 조건**: 타격된 공은 바닥에 닿기 전에 앞벽에 도달해야 한다. 가는 길에 옆벽/뒷벽을 먼저 맞는 건 허용. 상대는 바닥에 **두 번 튀기기 전에**(노바운드 발리 포함) 쳐야 한다.
- **실점 상황 (상대 득점)**
  - **투 바운드**: 공이 바닥에 두 번 튀기기 전에 치지 못함
  - **아웃**: 공이 벽 위쪽 아웃 라인(앞벽·옆벽·뒷벽)을 넘거나 라인에 맞음 (라인 위 = 아웃)
  - **틴**: 앞벽 하단 틴에 맞거나 그 아래로 떨어짐 (틴 윗선에 맞아도 틴)
  - **서브 미스**: 서브가 앞벽 서비스 라인 위(아웃 라인 아래)를 맞히지 못함, 또는 앞벽을 맞고 나온 공이 상대 쪽 뒤 사각형(숏 라인 뒤, 하프코트 라인 반대편)에 첫 바운드되지 않음. 단, 리시버가 첫 바운드 전에 발리로 받으면 서브는 유효.
  - 공이 앞벽에 닿기 전에 바닥에 닿음 (= 다운, 틴과 같은 취급)
- **판정 연출**: 실점 순간 짧은 슬로우 + 판정 텍스트(`OUT!`, `TIN!`, `DOUBLE BOUNCE`, `FAULT`)를 크게 띄워 왜 점수가 났는지 명확히 알려준다. 룰을 모르는 사람도 이걸로 배운다.
- **MVP에서 제외**: 렛/스트로크(방해), 선수에게 공이 맞는 경우, 타임아웃. 선수끼리는 서로 겹치지 않게만 처리.

### 3-5. 1인 모드

- 혼자 앞벽에 계속 치는 연습/스코어 어택. **본인이 멈추기 전까지 끝나지 않음**.
- 점수 = **연속 랠리 수(콤보)**. 아웃/틴/투 바운드가 나면 콤보만 0으로 리셋되고 공이 다시 서브됨 (게임오버 없음).
- 화면에 현재 콤보, 최고 콤보, PERFECT 횟수 표시. 최고 기록은 난이도별로 브라우저에 저장.
- 일시정지 → `그만하기`를 누르면 결과 화면(총 타구 수, 최고 콤보, PERFECT 비율) 후 메인으로.

### 3-6. AI 상대

- **공정함이 원칙**: AI도 플레이어와 같은 물리·같은 룰·같은 이동 속도 상한을 쓴다. 공 위치를 순간이동하듯 따라가지 않는다.
- 동작 흐름: 상대가 친 순간 → (반응 지연) → 공 궤적 예측 → 타점으로 이동 → 샷 선택 → 일정 확률로 판정 오차.
- 난이도별로 반응 지연, 예측 정확도, 실수 확률, 샷 다양성이 다르다 (3-2 표).
- AI 샷 선택 의도: 플레이어가 뒤쪽에 있으면 드롭, 앞쪽에 붙어 있으면 깊은 드라이브 — "흔드는" 플레이를 해야 스쿼시답다.
- AI가 타격할 때도 플레이어와 같은 타격음/이펙트(단, 화면 진동은 약하게 또는 없음).

### 3-7. 카메라

- 첨부 이미지 1처럼 **플레이어 캐릭터 등 뒤, 뒷벽(유리) 바깥 약간 위**에서 **앞벽을 정면으로** 내려다보는 3인칭 시점.
- 플레이어가 움직이면 카메라가 **부드럽게(지연을 두고) 조금만** 따라간다.
- **이동 한계**: 앞벽 전체와 좌우 옆벽 라인, 바닥 전체가 항상 화면 안에 들어오는 범위를 벗어나지 않는다. 난이도별 코트 크기가 달라도 이 원칙 유지.
- 상대(AI)가 앞에서 칠 때 플레이어 캐릭터가 공을 가리지 않도록 캐릭터를 살짝 반투명 처리하는 것도 검토.
- 화면 비율이 바뀌어도(가로/세로) 코트 전체가 보이도록 시야각을 맞춘다.

### 3-8. 타격감 (FX) — 플레이를 방해하지 않는 선에서 "확실히"

| 요소 | 의도 | 강도 가이드 |
|---|---|---|
| 히트스톱 | 맞는 순간 게임이 아주 잠깐 멈춤 | 일반 ~50ms, PERFECT ~80ms |
| 화면 진동 | 미세하게 흔들리고 빠르게 감쇠 | 아주 작게, 0.1~0.15초. PERFECT/강한 드라이브일수록 조금 더. 공·라인을 읽는 데 지장 없어야 함. 설정에서 끔/약/보통 |
| 임팩트 섬광 | 타점에 흰색/노란색 짧은 플래시 + 방사형 스파크 | 0.1초 내외 |
| 스윙 트레일 | 레퍼런스처럼 라켓 궤적을 따라 흰 호 | 드라이브는 길고 굵게, 드롭은 짧고 가늘게 |
| 공 잔상 | 공 속도에 비례하는 꼬리 | 빠를수록 길게 |
| 판정 텍스트 | `PERFECT` / `GOOD` 팝업 | 타점 근처에서 떠올랐다 사라짐 |
| 벽 자국 | 공이 앞벽에 맞은 자리에 먼지 링 | 잠깐 남았다가 페이드 |
| 득점 연출 | 점수 숫자 펀치 애니메이션 | 랠리 종료 후 |

- AI가 칠 때는 진동/히트스톱을 약하게 해서 "내가 쳤을 때"가 더 짜릿하게 차별화.

### 3-9. 사운드 (SFX)

**필요 목록**

| 분류 | 소리 | 비고 |
|---|---|---|
| UI | 버튼 호버, 클릭, 확인, 뒤로가기, 일시정지 | 가볍고 짧게 |
| 타격 | 라켓 타격 — 약(드롭/블록), 강(드라이브), PERFECT 전용 | 각 2~3개 변형, 재생 시 피치 랜덤 ±5% |
| 공 | 앞벽 바운드, 옆벽 바운드, 유리 뒷벽 바운드(더 맑은 소리), 바닥 바운드 | 공 속도에 따라 볼륨 차등 |
| 틴 | 금속 "땡" | 스쿼시 정체성 사운드 |
| 신발 | 스퀵(급정지/방향전환), 가벼운 발소리 | 플레이어·AI 모두. 스퀵은 연속 재생 쿨다운 |
| 결과 | 득점, 실점, 게임 승리, 매치 승리/패배 짧은 징글 | |
| (선택) | 관중 앰비언스, 득점 시 박수 | 아주 작게 |

**구하는 원칙**
- **비용 지불 없이**, 상업적 사용 가능, 가능하면 저작자 표기도 필요 없는 **CC0(퍼블릭 도메인)** 우선.
- 우선 후보: Kenney 사운드팩(CC0 — Impact Sounds에 발소리/충격음, Interface Sounds·UI Audio에 UI음), Freesound에서 라이선스 필터 `CC0`, OpenGameArt의 CC0 항목, Pixabay 효과음(Pixabay 라이선스: 무료·상업 가능·표기 불필요).
- **CC-BY-NC(비상업)나 출처가 불분명한 음원은 사용 금지.** CC-BY는 표기 의무가 있으니 가급적 피하고, 쓰면 크레딧 화면에 표기.
- 다운받은 모든 음원은 파일별로 출처 URL·작성자·라이선스를 기록한 크레딧 문서를 남긴다.
- 로그인이 필요해 자동 다운로드가 안 되는 사이트(Freesound 등)는 후보 URL 목록을 만들어 사용자에게 수동 다운로드를 요청한다.
- 원하는 소리가 없을 때의 최후 수단: 브라우저 오디오 합성으로 임시 사운드를 만들어 두고 나중에 교체.
- 레퍼런스처럼 **배경음악은 없거나 아주 작게**. 타격음이 주인공.

### 3-10. 화면 흐름

```
타이틀 → 메인 메뉴 ─┬─ 1인 모드 → 난이도 선택 → 플레이(무한) → 일시정지 → 그만하기 → 결과 → 메인
                    ├─ AI 대전 → 난이도 선택 → 매치(게임1~3) → 매치 결과 → 메인 / 재대결
                    ├─ 조작법(짧은 애니메이션 튜토리얼: 드라이브/드롭 제스처 시연)
                    └─ 설정(효과음/화면 진동 세기/자동 위치 보조)
```

- 첫 플레이 시 3초짜리 조작 안내 오버레이(레퍼런스처럼 하단 한 줄 안내는 상시 표시).
- **HUD (AI 대전)**: 화면 **상단 중앙**에 `나 [게임 스코어] 현재 점수 : 현재 점수 [게임 스코어] AI` + 서브권 표시. 첨부 이미지 1처럼 앞벽에 큰 숫자로 점수를 비춰주는 연출도 함께 쓰면 좋음.

### 3-11. 비주얼 방향

- 레퍼런스의 **플랫 카툰 + 검은 외곽선 + 보라 계열 아레나** 톤을 가져가되, 더 심플하고 깔끔하게.
- 디자인 기준 이미지(키 이미지, 캐릭터 시트, UI 킷 등)는 사용자가 GPT로 먼저 생성해 `assets/design/` 에 넣는다 (`02_GPT_디자인_프롬프트.md` 참고).
- 이미지가 아직 없어도 개발은 진행 가능해야 한다 — 단색/기본 도형으로 먼저 만들고, 이미지가 들어오면 그 톤에 맞춰 재질·색·UI를 교체.
- 스폰서 보드 등에 실존 브랜드/협회 로고는 쓰지 않고 가상의 이름만 사용.

## 6. 미결정 / 추후 결정 항목

1. **이동 방식**: 제안은 `WASD 이동 + 마우스 스윙` (+쉬움에서 자동 위치 보조). 마우스만으로 하는 완전 자동 이동을 원하면 변경.
2. **드라이브/드롭 방향 매핑**: 레퍼런스 안내문대로 `아래→위 = 드라이브`, `위→아래 = 드롭`으로 정함. 반대를 원하면 설정값 하나로 바뀌게 만들어 둘 것.
3. **난이도별 높이 라인**: 코트가 좁아질 때 아웃 라인/틴 높이도 같이 줄일지 — 플레이 테스트 후 결정.
4. **게임 이름**: 가제 `SQUASH RALLY`. 로고 작업 전 확정 필요.
5. **모바일 지원 시점**: MVP 이후로 미뤄둠. 링크 공유로 폰에서 여는 사람이 많을 것 같으면 우선순위 상향.
6. **배포처**: GitHub Pages / Vercel / Netlify 중 택1 (GitHub 계정 ovencub 사용 가정).

## 7. 변경 이력

### 2026-10-15 · M1 플레이 피드백 반영 (사용자 결정)
- **샷을 드라이브 하나로 단순화.** 드롭/블록 제거. 드롭이 난이도를 과하게 올림.
  - 조작: `↓당겼다 ↑밀기` = 풀 스윙 드라이브, 짧게 `클릭` = 가벼운 드라이브(파워 낮음).
- **플레이어 드라이브는 100% 유효.** 아웃/틴/다운이 나지 않도록 발사 전에 시뮬레이션으로 검증·보정. 상황(타이밍·위치)에 따라 각도와 속도만 달라짐.
  - 타이밍: PERFECT = 가장 빠르고 낮고 깊게, GOOD = 보통, EARLY/LATE = 느리고 높게.
  - 일찍 치면 크로스, 늦게 치면 스트레이트.
- **승패는 스윙 타이밍 + 타점까지의 위치 선정**으로만 갈린다. 실점 = 공을 못 받음(투 바운드).
- 쉬움 코트를 실제 규격보다 크게 (길이 1.15 × 폭 1.12) — M0 피드백.
- 룰 엔진의 아웃/틴/서브 판정은 그대로 유지 (AI 대전·서브에서 사용 가능, 테스트 유지).

### 2026-10-15 · M3 플레이 피드백 반영 (사용자 결정)
- **자동 위치 보조 삭제.** 모든 난이도에서 WASD 수동 이동만. 대신 이동 속도 상향(최고 7m/s, 튜닝 대상).
- **스윙 = 클릭만.** 우클릭 = 포핸드, 좌클릭 = 백핸드. 스트로크 제스처 삭제.
  - 타격 범위(캐릭터 주변 원)를 좌우 절반으로 나눠, 공이 오른쪽 절반이면 포핸드만, 왼쪽 절반이면 백핸드만 맞는다. 반대 손 = 헛스윙.
- **타구 세기 = 거리 배점 × 타이밍 배점.**
  - 거리 배점: 범위 반지름의 50% 지점 원(최적 원)에서 최고, 안쪽/바깥쪽으로 갈수록 낮아지고, 범위 밖이면 타격 안 됨. (비율은 설정값 `timing.sweetRatio`)
  - 타이밍 배점: 기존과 같이 이상적인 순간과의 오차.
  - 배점 높을수록 빠르고 낮고 깊게 (12 → 26 m/s). 여전히 100% 유효 샷.
- **타격 방향 = 클릭 순간 커서 위치** (캐릭터 → 커서 방향이 앞벽과 만나는 곳).
- 캐릭터에 **팔꿈치·무릎 관절** 추가, 준비 자세/달리기/옆 스텝/백페달/런지 스윙 절차 애니메이션.
- 타격음 밝게 + 코트 리버브, 화면 진동 강화, 히트스톱 때 캐릭터·라켓까지 멈춤.

### 2026-10-15 · M3 2차 피드백 / M4
- 이동 속도는 사용자 설정 (플레이 중 HUD 슬라이더로도 조절, 기본 6.3m/s).
- 난이도 = 코트 크기 + **게임 진행 속도 배율(A안)**: 쉬움 1.0 / 보통 1.15 / 어려움 1.35. 좁은 코트가 오히려 쉬워지던 문제 보완.
- AI 대전: AI도 같은 물리·룰·이동 모델·타격 판정. 난이도별 반응 지연, 위치 오차, 타이밍 오차, 이동 속도, 판단 실수 확률, 노리는 방향이 다름.
- 서브는 클릭 한 번 (항상 유효한 서브 궤적). AI 서브는 1초 뒤 자동.

### 2026-10-15 · M6 (디자인 이미지 없이 팔레트 기반으로 1차 적용)
- 아레나: 좌우 3단 관중석 + 관중 실루엣(득점·PERFECT 때 들썩임), 바깥 바닥 패턴과 코트 주변 조명 번짐, 관중석 앞 가상 스폰서 광고판, 유리벽 프레임 기둥.
- 코트: 벽 그라데이션·패널 이음매·옅은 공 자국, 틴 하이라이트.
- 캐릭터: 굵은 검은 외곽선, 흰 신발 + 포인트색 밑창, 양말, 유니폼 줄무늬·칼라, 손목 밴드, 얼굴(눈), 발밑 그림자.
- UI: 한글 웹폰트(Black Han Sans, Noto Sans KR), 라켓 아이콘 로고, 메뉴 패널·버튼 다듬기.

### 2026-10-15 · AI 대전 수정
- **버그: 플레이어의 첫 서브를 AI가 항상 못 받음** → 원인: 게임 랜덤 시드가 고정이라 매 경기 첫 "판단 실수" 추첨 결과가 항상 같았음(=실수). 시드를 경기마다 새로 뽑도록 수정 (회귀 테스트: 첫 서브 리시브 18/18).
- **AI가 놓칠 확률을 플레이어 샷 난이도에 연동** (기존: 난이도별 고정 확률):
  - 놓칠 확률 = 기본값 + 급함 가중치 × (필요 이동 속도 / AI 최고 속도) + 빠르기 가중치 × (타구 속력)
  - 급하고 빠를수록 타이밍 오차도 커져서 받아도 약하게 넘어옴. 물리적으로 못 닿는 공은 원래대로 못 받음.
  - 서브는 속력이 자동이므로 빠르기 가산 없음. 값은 `tuning.ai.level`(missBase / missPressure / missSpeed / timingRush).
